# Opt-in public section generation planning

Trusted Python host configuration enables planning with nonempty
`ReviewPolicy.public_objectives`, existing coverage facets and a private
ReviewContract. Real adapters must use the named-functions section protocol;
HTTP and model data cannot turn this policy on. The default remains off,
and legacy JSON schemas still expose only tools/final without plan sidecars.

Public objectives must come from the user's task or public section objective.
Private expected answers never become authoring instructions. The contract's
digest binds review identity; its requirement text stays in independent review.
Host authors remain responsible for not copying answers into PublicBrief.

After persisted accepted source feedback, a public plan maps authoring objective
numbers to current f:n/c:n projection rows or explicit gaps. These row numbers
are scoped to the current source and coverage digests. Unplanned rows stay
visible, without making every syntax row a mandatory prose fact. The plan event
persists only its SHA256; plan contents remain in bounded derived context and
the immutable held candidate. Source observations and tool history are retained.

The native protocol has three stages: read (source tools or terminal gap),
planning (source tools or submit_coverage_plan), prose (final actions only).
The engine rejects a section before a bound plan, repeated plans, and any new
source tools after planning, including scripted attempts that bypass the native
schema. A submitted plan is public structured data, not private reasoning.

Read, plan and final requests share the original six-model-call, twelve-tool,
30-second, 24000-ModelContext-character, 12000-output-character and 4000-output-
token limits with zero retries. Plan and final claim sidecars are charged by the
existing accounting path. The complete derived context is measured before the
adapter reserves fees or dispatches HTTP. Compact profile's existing 2400-token
minimum prose reserve remains: below it, only gap/clarification is available.
Request byte limits remain separate; no excerpts are clipped or caps expanded.

The original final is frozen once. Exact unique final-body claims bind planned
targets to quoted spans and source citations. A report and public plan are
stored with the existing held candidate in the original size limit. Missing
claims, ID-only lists, uncited statements and unproved positive relationships
veto release even if an independent reviewer mistakenly marks all private
criteria pass. Explicit unknown statements remain review data and are not
automatically failed solely for retaining a legitimate gap. Existing source-call
audit and independent whole-body review still apply; known uncertainty-language
limitations have not been repaired here. The final body is never rewritten.

Structural completeness is not entailment: a wrong constant can have correctly
bound spans. All reports remain semantic_verified=false/publication_approval=false;
only the original independent review/atomic publication path can release the
unaltered output. Rejection receipts retain the generation report and reasons.

All evidence for this integration is scripted or Mock HTTP against isolated
Git/SQLite and synthetic billing ledgers. It is not live S03 quality acceptance,
active installation or proof that any future prose fits the remaining budget.
