# Bounded call context and independent source-assisted publication

Explicit host ReviewPolicy now supplies a single derived call-data entry in each
section ModelContext, rebuilt from that current task's accepted reads. Before
the first accepted read it supplies nothing. The entry is measured with the
whole context under the original 24k cap before model dispatch/reservation;
8192 is only the projection's own cap. No truncation, source expansion, name-
based receiver inference, answer injection or larger model/output budget exists.
The native function/output schema remains unchanged. Call data is not authority.

The collector observes the existing SourceTools instance after the base byte
checks instead of replacing it with a plain tool. RangedSourceTools and sealed
S03 subclasses retain their original range masks/digest overrides. Hooks are
chained/restored and cannot mint a blob if a subclass bypasses the verified base
read. No additional read or output field is introduced. The initial exact-base-
class restriction was found during entry integration and corrected before Key
input or paid calls; dedicated observer/range regression evidence is retained.

All generated section candidates remain frozen needs_review. The host can also
configure a ReviewContract and call TaskService.review_held with a HostReviewer
inside the same process. No HTTP/model tool can select a reviewer, submit review
authority or release. The original submission golden is preserved byte-for-byte
under schemas/submission-review-golden.json (SHA256 602c000c...717b21f); the loader
pins it and selects all six original M2-S03 criteria. Criteria are never generated
from the candidate. The production entry must bind that exact contract/section.

The reviewer receives a detached packet containing the whole original output,
all field hashes (title/headings/text including diagrams/gaps), every criterion,
actual accepted source text, index and call audit. Its strict assessment must
bind the current task/output/index/contract, cover each field exactly once, and
judge every criterion once. Passed criteria need unique original body quotes
and exact non-truncated actual-source line quotes cited by those body blocks.
Unknown/missing criteria, critical findings, call-audit findings, missing call
sidecars for recognized language, stale/forged quotes or digest mismatches cannot
release. A no-findings call scan is never an independent review on its own.

HostReviewer is an explicit trusted-host configuration boundary, not proof that
a string reviewer identity is independent or that quote matching proves logical
entailment. The host reviewer must actually inspect support and all critical
claims. No built-in positive reviewer or model-review request exists. Tests use
scripted judgements and are labelled accordingly; scripted review cannot approve
a real task. A host source-assisted pass remains distinct from runtime proof,
personal acceptance and the native semantic_verified/quality_verified fields,
which remain false. Reviewer reasons pass existing sensitive-content checks;
source quotes must match the already admitted public excerpt exactly.

CheckedReview, FrozenCandidate and the live accepted-read collector cannot be
minted by deserializing model/HTTP/archive JSON. Only eight live held candidates
and eight append-only receipts per task are retained. Receipt/packet caps are
64k/128k bytes, separate from the original model budget. Review has a cooperative
30-second deadline and cancellation/source checks before and after the callback.
Re-verification, version change, deletion, cancellation, duplicate review or
restart cannot recreate release authority. Archive JSON remains readable. The
live collector/candidate and original source-session identity must still exist.

ReviewStore performs an exact task/project/commit/needs_review CAS inside the
same transaction as LearningStore publication and its receipt. The original
TaskStore._write active-only rule is unchanged. A pass publishes the original
body once; a failed criterion/audit stores review_rejected with original reasons
and no learning body. Database failure rolls back task/learning/positive receipt;
bounded failure diagnostics are appended and the original remains held. A host
may fix a malformed review or storage failure and review the same immutable
candidate without another model call; semantic rejection is terminal. Cancelled
or otherwise terminal tasks cannot be revived by this path.

Receipt summaries are additive in task GET; old/default services need no new
table to read old tasks. Candidate snapshots and all receipts are immutable;
project deletion cascades only within assistant-owned tables. review_rejected
has a visible unpublished label. Native and both existing follow-up input seals
include the new review, contract, source-session and publication dependencies.

Validation: 572 related engine/protocol/source/call/native-adapter/storage/API
checks and three frontend scripts pass. The original S03 five-read/211-line
replay carries all 48 calls into a static native frame (19284 context characters,
34251 request bytes), and its pinned six-criterion review still rejects at 5/6.
Original artifacts, output, grade, database rows and fees are unchanged. This is
offline/scripted/static validation, not a new provider response or evidence of
improved real generation. A dedicated newly sealed single-use trial entry and
fresh quota/price/source/readiness checks remain necessary before a paid task.
