# Host-configured source coverage in the controlled section loop

`ReviewPolicy(..., coverage_facets=('branches', 'queries', 'snapshot_fields',
'writes', 'payload_response'))` explicitly enables the combined syntax view.
The default empty tuple retains the old call-only view. This is trusted host
configuration, not an HTTP/model option or source/publication permission.
Direct parameter column values have a separate `write_inputs` facet; `writes`
contains other SQL values/expressions and must not be described as all constants.

The existing TaskService read observer, ProjectStore evidence transaction and
persisted `tool_feedback_accepted` event precede collection. Only that same
current AcceptedReads instance can mint a grouped view through its original
index binding. No data is injected before the first accepted read. Each model
step rebuilds from the current accepted set; frozen or stale/foreign material
cannot be used. Complete verified blobs supply lexical context, while exported
facts must fit within one admitted read; ranges cannot be stitched. The host
inventory is bounded to 256 items/128k bytes, and the compact view to 8192 chars.
Unknown parser forms remain gaps. Non-finite JSON literals are rejected as gaps.

The loop receives one `host_source_coverage` entry instead of the old derived
call-only entry. It retains original observations, other history and calls.
The engine's existing checkpoint runs after projection and before generation;
source session, selected version and cancellation therefore retain precedence.
The original complete ModelContext serialization is measured against 24000
before adapter generation/ledger reservation. No original code excerpts are
clipped and no budget or retry count is increased. The 128k request-byte guard
remains separate from the ModelContext character budget, as before.

The view is syntax data, not a list of mandatory facts, a model plan, a semantic
score or a publication permit. Host grouping is explicit configuration, not
automatic comprehension of arbitrary questions. The original candidate is still
held; independent whole-output review and atomic release/rejection are unchanged.
There is no positive reviewer, answer repair or golden-answer prompt injection.
The source calls used by the independent reviewer retain their original opaque
index/call IDs, regardless of the compact model-view row indexes.

Mock integration checks actual database persistence and feedback events before
the view reaches the adapter, cancellation/version/session revocation, failed
save/event handling, projection/full-context overflow, freeze, immutable hold and
independent release. A Mock native request checks that combined data reaches the
wire unchanged. Another Mock path demonstrates that overflow after a first read
does not make a second ledger reservation or HTTP request, with the first valid
receipt settled. Historical source metadata and missing-usage fixture failures
are preserved; the guards that rejected them were not relaxed.

No active installation, provider calls, real budget grants or new trial entry
were made. Pre-generation coverage planning, final-body coverage judgement and
the known uncertainty-language limitations remain unfinished; source grouping
and lifecycle tests do not establish improved real-model explanation quality.
