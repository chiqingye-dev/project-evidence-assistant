## 结果怎样理解

初批提示混入旧正文合同，基线又被要求调用已禁用工具；允许行范围只放在 Schema 中，模型多次请求从第 1 行读取并被拒。真实响应明确定位后，修复了请求指令、显式范围和 Schema 默认值。没有改变题目、读取权限、标准或预算。初批费用 ¥0.551714，没有删掉这些失败。

修订批两种方法均为 30/30 格式通过、30/30 自动词组检查通过，且没有触发正文校验纠正；这次真实批次不能证明纠正机制的实际改善幅度，纠正边界由模拟 HTTP 回归覆盖。基线也全部通过且更省费用与时间，这套给定入口的小题集没有证明 Agent 优于简单检索。

**上述 100% 不是语义正确率。** 开发者逐份抽查了修订批每题、每方法的第 1 次输出，共 20 份，并对照允许源码。至少发现三类自动检查漏检：

- Q-sql / agent / 第1次：把按 slug 查询加 LIMIT 1 扩大为唯一键判断，当前片段没有唯一约束。
- C-parser / agent / 第1次：补充 Jackson 默认配置及调用方只需处理一种异常，当前片段不支持这些额外结论。
- G-cache / 两种方法 / 第1次：保留 TTL 未知，却又断言未命中时回源；调用点只能证明传入 lambda，不能证明被调实现何时调用它。

这是开发者源码辅助定性复核，不是独立盲评；没有给全部 60 份输出的语义通过率，也没有把未指出问题的样本自动记为语义合格。引用 ID 正确和缺口词语出现，均不能代替断言支持检查。
