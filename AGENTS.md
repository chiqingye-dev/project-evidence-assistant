# Development rules

- Main is the integration branch. Keep new code readable; no semicolon-packed code or source-rewriting scripts.
- Normal section output contains text blocks and current evidence IDs. Host code derives titles, section IDs and block locations; do not require model-authored coverage claims.
- Preserve fixed-source, path, secret, budget and cancellation boundaries. Never read or index `docs/M2-NEXT-CHAT-HANDOFF.md` or `.smtp.qq.local` in a learning target.
- Store credential-redacted raw responses under ignored `data/`. Read credentials from environment variables; never print or commit them.
- Correct validation failures at most twice within shared task budgets. Source, permission and billing failures are not correctable output errors.
- Use the existing cumulative ledger; never reset history or add grants to bypass limits.
- S03 is a documented development failure, not a release gate or target for further trials.
- Use a small fixed development benchmark, repeated trials and a retrieval baseline. Protocol success and content review are separate; developer self-review is not independent blind evaluation.
- Keep one short progress file. No new per-run entry points, seals, manifests or historical verification chains. Preserve historical evidence.
- Do not delete worktrees or stop unrelated apps/services. Never close or restart Codex/ChatGPT without explicit user instruction.
