# 固定开发评测的口径

`fixed_v05.json` 在第一批真实请求前固定。10 题、每题 3 次、两种方法，覆盖查询、提交、消息与判题，并包含缓存和隔离两道缺证据题。S03 不在题集中。

两种方法用同一 deepseek-flash、temperature=0、相同输出合同和单任务预算。Agent 自选受限只读工具；基线先按关键词在相同允许片段池中排序取 top 2，再让模型生成，不能请求更多工具。基线的检索耗时计入总耗时，候选片段评分属于宿主检索，不冒充模型工具调用。

- **无纠正格式通过**：最终状态符合该题预期且未触发正文校验纠正；可以包含正常的多轮源码读取，不是“第一次HTTP响应就完成”。
- **纠正后格式通过**：在同一预算和最多两次纠正内完成；缺证据题接受明确 gap。
- **自动要点检查**：输出覆盖题集中预设的词组，不检查全部断言、否定方向、引用与断言的对应关系。
- **内容复核**：开发者阅读原文和源码的定性检查，必须注明样本范围。不是独立盲评，不与自动要点检查混称语义正确率。
- **费用**：同一个本机累计账本的保守高峰单价上界；全部失败和纠正计入，不能当作供应商真实余额。

这是已知项目、给定入口和受限片段的开发集，每题 3 次不能估计稳定泛化能力。题目大多只有 1–3 个片段，检索基线很强；Agent 即使全部通过也不能据此宣称优于检索。

0.5 初批发现提示仍混入旧协议，且基线被要求调用已禁用工具。保留完整初批，修复请求构造后对相同题集再跑一批，分别报告。修订批属于观察失败后的开发验证，不是新的未见测试。逐次结果、供应商响应和费用留在本机 data 下，公共报告不附 Key 或本机数据库。
